# Milestone 3.5 Source Compatibility POC

> 依使用者明確的四階段需求，使用 executing-plans／test-driven-development 在現有工作區實作。無 Git，不建立工作樹或提交。

**Goal:** 以相同 DeckEngine 與 WebAudioSession 驗證本機控制來源及 Audius 的可聽見輸出。
**Architecture:** MusicProvider.search/resolve → normalized Track/AudioSource → 既有 DeckEngine → 既有 Web Audio source/gain/output。移動共用契約中的 YouTube host 限制至 YouTube service，原限制與 anonymous CORS 不變。測試訊號量測僅放在獨立 harness。
**Spec:** 使用者 2026-10-06 Milestone 3.5 完整需求；不實作 Milestone 4。

## Constraints / Review Focus

- 先測本機：本機失敗時停止 Audius 實作，調查 confirmed cause。
- 不下載遠端音樂、不使用 proxy/mpv/native PCM engine、不變更 YouTube CORS。
- Track 只加可選 provider 標記，既有 YouTube Track 與測試相容。
- 舊 YouTube resolve 驗證須繼續拒絕非 googlevideo、credentials 與新增但不適用的 MIME。
- 本機來源僅以同源內建合法測試資產提供；不是另一個播放器。
- 真實 PASS 需要使用者聽感確認，加上 Gain 後訊號量測及播放器狀態證據。
- HTTP200、測試替身或 Gain.value 變化不能單独作為 PASS。

## Rulings / Evidence

- Ruling: 不重寫引擎；共用驗證中的 provider host 耦合須移到 YouTube adapter，代價是各 provider 必須自己保留來源政策。
- Ruling: 聽感是必要且不可由模型猜測的證據。缺少聽感時標示未驗證，不稱 PASS、不自動開始 Milestone 4。
- Ruling: 本機 pause 初次測試的快照差 0.211539 秒可能為 timeupdate 延遲；改驗證實際 media.currentTime 停止與 paused，另記快照修正量。不據此重寫引擎。
- Evidence: 使用者確認本機可聽見而且音量變小後靜音；media pause drift=0，Gain RMS=0.082668/0.020641/0，dispose context closed。
- Evidence: 真實 Audius GET track data 為物件，已補紅綠測試並修正 adapter。validator signed stream HEAD200/Range206，MP3/CORS*；也觀察到未驗證 monophonic 節點，保持明確拒絕。
- Handoff: 使用者要求自行操作部分功能測試。Audius native ready/audible/Gain/seek/replacement/cleanup 待回報；不宣告 Milestone 3.5 全部驗收、不開始 Milestone 4。
