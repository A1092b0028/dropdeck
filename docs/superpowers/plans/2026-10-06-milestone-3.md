# Milestone 3 Audio Engine POC Implementation Plan

> 使用 superpowers:executing-plans 在本工作區依序實作，最後進行獨立審查。

**Goal:** 驗證 YouTube audio-only 來源可以進入 Web Audio Gain 管線，啟用 Deck A 最小控制。

**Architecture:** YouTubeService.resolve → Tauri → Rust → yt-dlp；DeckEngine 管理狀態與競態，WebAudioSession 管理媒體與 Source → Gain → Output，React 僅訂閱狀態。

**Tech Stack:** 現有 React、TypeScript、Tauri、serde、tokio 與 Web Audio；不新增播放器依賴。

**Spec:** ../specs/2026-10-06-milestone-3-audio-engine-design.md

## Global Constraints

- 僅 Milestone 3；Deck B、EQ、Mixer、tempo、waveform 維持未啟用。
- UI 不呼叫 yt-dlp；現有搜尋介面與測試保留。
- 直連来源需 CORS；不能以繞過處理圖的播放掩蓋失敗。
- 使用者已確認設計並要求繼續實作驗證；本次由主代理直接執行。

## Review Focus

- 播放中換曲、unload、過時的 resolve/play completion 不得恢復舊媒體。
- duration 未知或無 seekable range 時不能假裝可以 seek。
- 解析資料不能接受任意 URL、playlist 或 yt-dlp 結構。
- 原生 CORS／格式／來源失敗需與單元測試成功分開報告。
- React StrictMode 重掛載與 dispose 必須釋放事件、媒體與 context。
